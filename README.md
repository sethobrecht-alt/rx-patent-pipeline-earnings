# Rx Patent Expiration Tracker

A static website that tracks upcoming drug patent / exclusivity expirations
(the "patent cliff") and the generic and biosimilar competition lining up
behind them — built for monitoring the market, not for legal or investment
decisions. It has three pages: the **Patent Expirations** tracker for
approved drugs, a **Specialty Pipeline** page for late-stage drugs that
haven't been approved yet, and an **Earnings** page tracking quarterly
revenue, profit, and product-level performance for publicly traded pharma
manufacturers.

**Live data sources (Patent Expirations page):** [FDA Orange Book Data Files](https://www.fda.gov/drugs/drug-approvals-and-databases/orange-book-data-files)
(small-molecule drugs) and the [FDA Purple Book](https://purplebooksearch.fda.gov/downloads)
(biologics / biosimilars), refreshed automatically once a month. Biosimilar
and generic *competitive intelligence* (settlement dates, expected launches)
is hand-curated from public reporting, since that information doesn't live
in either FDA database — see `scripts/curated_overrides.json`.

**Specialty Pipeline page:** entirely hand-curated research (`scripts/curated_pipeline.json`).
There's no FDA database for drugs that aren't approved yet, so unlike the
main page this one has no live/automated source — it needs periodic manual
(or AI-assisted) research to stay current as drugs get approved, fail
trials, or shift timelines.

**Earnings page:** entirely hand-curated research (`scripts/curated_earnings.json`),
covering 48 publicly traded pharmaceutical and biotech manufacturers across
large, mid, and small market-cap tiers. There's no live financial data feed
wired up here either — each company's latest-quarter revenue, profit, and
product-level call-outs come from its own earnings press releases and
filings, researched at a point in time. Like the pipeline page, it needs a
periodic manual (or AI-assisted) refresh each earnings season to stay
current.

## How it's put together

```
site/                    the static site itself — deploy this folder as-is
  index.html               Patent Expirations page
  pipeline.html            Specialty Pipeline page
  earnings.html            Earnings page
  assets/app.js            front end for index.html: table + timeline + detail drawer
  assets/pipeline.js       front end for pipeline.html (same pattern, pipeline schema)
  assets/earnings.js       front end for earnings.html (same pattern, earnings schema)
  assets/styles.css        shared stylesheet for all three pages
  data/drugs.json          <- generated by scripts/build_data.py, read by app.js
  data/pipeline.json       <- generated by scripts/build_pipeline_data.py, read by pipeline.js
  data/earnings.json       <- generated by scripts/build_earnings_data.py, read by earnings.js
  CNAME                    custom domain for GitHub Pages (placeholder: rxpatentexpiry.ai
                            -- swap for whatever domain you actually register, see below)

scripts/
  build_data.py            pipeline: pulls Orange Book + Purple Book, merges with the
                            curated overlay below, writes site/data/drugs.json
  curated_overrides.json   hand-maintained watchlist: which drugs to track, plus
                            biosimilar/generic competitor intel and source links.
                            NOT overwritten by the pipeline -- edit this file to add
                            or update a drug.
  build_pipeline_data.py   validates and republishes curated_pipeline.json as
                            site/data/pipeline.json (no live source to merge -- see above)
  curated_pipeline.json    hand-maintained watchlist of late-stage, not-yet-approved
                            specialty drugs: developer, modality, phase, expected
                            launch, administration setting, peak sales projection,
                            sources. Edit this file to add, update, or graduate a
                            drug (once approved, move it to curated_overrides.json).
  build_earnings_data.py   validates and republishes curated_earnings.json as
                            site/data/earnings.json (no live source -- see above)
  curated_earnings.json    hand-maintained watchlist of 48 publicly traded pharma/
                            biotech manufacturers: ticker, market-cap tier, latest-
                            quarter revenue + profit (with YoY growth), product-level
                            call-outs, sources. Edit this file to add a company or
                            refresh figures for a new quarter.
  build_standalone.py      inlines a page + its JS + its data into a single
                            self-contained HTML file (no server needed) -- used for
                            quick-look copies, not for deployment.
  requirements.txt

.github/workflows/update-data.yml
                            GitHub Action: runs all three data pipelines on the 25th
                            of every month and on every push, commits the refreshed
                            data/*.json files, and redeploys to GitHub Pages. This
                            only fires once the repo is actually pushed to GitHub
                            with Actions enabled -- see "Deploying it" below.
```

## Keeping all three pages current, automatically

Patent Expirations pulls live data every run (FDA Orange/Purple Book), so
the GitHub Action alone keeps it current. Specialty Pipeline and Earnings
have no live source -- their content only changes when `curated_pipeline.json`
/ `curated_earnings.json` are actually re-researched and edited. To keep all
three pages updating together on the same monthly cadence, there are two
pieces working together, both scheduled for the 25th of each month:

1. **A Claude scheduled task** (set up outside this repo, in the Claude app)
   does the actual research: it re-checks the Specialty Pipeline drugs and
   all 48 tracked Earnings companies for anything that's changed (new
   approvals, phase/timeline shifts, a new quarter's results, M&A activity),
   updates `curated_pipeline.json` and `curated_earnings.json` accordingly,
   rebuilds the standalone preview files, and refreshes the deliverables.
   The full instructions it follows live in the Claude Project ("Rx Patent
   Expiration") as `claude/monthly-refresh-playbook.md`, since a scheduled
   task starts a fresh session each time with no memory of this repo.
2. **The GitHub Action** above (once deployed) picks up whatever's in the
   `curated_*.json` files, re-pulls live FDA data for Patent Expirations,
   rebuilds all three `site/data/*.json` files, and redeploys.

If the site isn't deployed to GitHub yet, step 2 doesn't have anywhere to
run -- the Claude scheduled task still does its research and refreshes the
standalone files and delivered zips directly, so the site stays current
either way, deployed or not.

## Deploying it (GitHub Pages, free)

1. Create a new **public** GitHub repo and push this folder to it:
   ```bash
   cd rx-patent-tracker
   git init
   git add .
   git commit -m "Initial site"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo-name>.git
   git push -u origin main
   ```
2. In the repo on GitHub: **Settings → Pages → Build and deployment → Source**,
   choose **GitHub Actions**.
3. Also check **Settings → Actions → General → Workflow permissions** and make
   sure "Read and write permissions" is selected (needed so the scheduled run
   can commit the refreshed data file).
4. Push (or go to the **Actions** tab and run "Update patent data and deploy"
   manually via *Run workflow*). After it finishes, your site is live at
   `https://<you>.github.io/<repo-name>/`.

From then on, it updates itself automatically once a month — no server, no
database, no ongoing cost.

### Connecting a custom domain (e.g. rxpatentexpiry.ai)

The repo already includes `site/CNAME` containing `rxpatentexpiry.ai` as a
placeholder — GitHub Pages reads this file to know which custom domain to
serve the site on. **This only works once you actually own that domain (or
whichever one you swap in)** — I can't register or buy a domain on your
behalf, that's a step only you can do at a registrar (Namecheap, Porkbun,
Google Domains, Cloudflare Registrar, etc., or by making an offer to the
current owner if you specifically want `rxpatentexpiry.ai`, which was
already registered and listed for resale as of this writing). If you land
on a different domain, open `site/CNAME` and replace the contents with your
domain (just the domain, no `http://`, no trailing slash).

Once you own the domain:

1. **At your registrar/DNS provider**, add these records (exact steps vary
   by registrar, but the records are standard for GitHub Pages):
   - For an apex/root domain (`rxpatentexpiry.ai`): four `A` records
     pointing at GitHub Pages' IPs —
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
     `185.199.111.153` — plus an `AAAA` set if you want IPv6
     (`2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`,
     `2606:50c0:8003::153`). Some registrars call this "ALIAS" or "ANAME"
     instead of `A` for apex domains — use whichever your registrar
     supports.
   - For a `www` subdomain instead: a single `CNAME` record pointing to
     `<you>.github.io`.
2. **In the repo**: **Settings → Pages → Custom domain**, enter the domain,
   save, and wait for GitHub to verify DNS (can take a few minutes to a few
   hours). Once verified, check **Enforce HTTPS** so the site serves over
   `https://`.
3. DNS propagation can take anywhere from a few minutes to 24-48 hours
   depending on your registrar and existing DNS records.

Until you complete these steps, the site is still fully reachable at the
free `https://<you>.github.io/<repo-name>/` address from the section above
— the custom domain is additive, not a replacement dependency.

### Alternative hosts

The `site/` folder is a plain static site, so it also deploys as-is to
Netlify or Vercel (drag-and-drop the `site/` folder, or point a Netlify
Deploy or Vercel project at this repo with `site` as the publish directory).
If you go that route, the scheduled *data refresh* still needs somewhere to
run — GitHub Actions works even if Pages isn't your host: just drop the
`deploy` job from the workflow and instead trigger your host's deploy hook
after `build_data.py` runs.

## Running the pipelines locally

```bash
cd scripts
pip install -r requirements.txt
python build_data.py                 # fetches live FDA data for the Patent Expirations page
python build_data.py --offline       # skips network calls, rebuilds from curated_overrides.json only
python build_pipeline_data.py        # rebuilds the Specialty Pipeline page's data (always offline --
                                      # there's no live source, it just validates/republishes the JSON)
python build_earnings_data.py        # rebuilds the Earnings page's data (also always offline)
```

## Adding or updating a tracked drug

**Patent Expirations page:** edit `scripts/curated_overrides.json` — add an
entry keyed by a short id, following the shape of the existing entries
(`brand_name`, `generic_name`, `company`, `type`: `"small_molecule"` or
`"biologic"`, `indication`, `competition`, `notes`, `sources`, `sales_2025`,
`administration`). The brand name is used to match against the live Orange
Book / Purple Book pull (best-effort, by normalized name); if a drug isn't
in either FDA database yet (e.g. still in Phase 3), the curated date is used
as-is.

**Specialty Pipeline page:** edit `scripts/curated_pipeline.json` — add an
entry keyed by a short id, following the shape of the existing entries
(`drug_name`, `developer`, `modality`: `"small_molecule"`, `"biologic"`, or
`"cell_gene_therapy"`, `indication`, `development_phase`, `expected_launch`,
`administration`, `peak_sales_projection`, `notes`, `sources`). When a
pipeline drug gets FDA approval, move (don't copy) its entry over to
`curated_overrides.json` in the shape that file expects, and remove it from
`curated_pipeline.json` — the Specialty Pipeline page is meant to only show
drugs that aren't approved yet. Then run `python build_pipeline_data.py`
(and `build_data.py` if you also updated `curated_overrides.json`).

**Earnings page:** edit `scripts/curated_earnings.json` — add an entry
keyed by a short id, following the shape of the existing entries
(`company_name`, `ticker`, `exchange`, `hq_country`, `tier`: `"large"`,
`"mid"`, or `"small"`, `latest_quarter`, `revenue`, `profit`,
`product_highlights`, `notes`, `sources`). Each quarter, revisit every
tracked company's latest earnings release and update `latest_quarter`,
`revenue`, `profit`, and `product_highlights` — there's no automated feed
for this, it's a manual (or AI-assisted) refresh. If a tracked company is
acquired, set `"status": "acquired"` (or `"pending_acquisition"` if the
deal hasn't closed yet) plus a `status_note` explaining the deal, and leave
its last-reported-quarter figures in place rather than deleting the entry.
Then run `python build_earnings_data.py`.

Each company's `product_highlights` also drive a **"Quarter driver" badge**
shown in the table and detail drawer — the front end (`assets/earnings.js`)
computes which product had the largest estimated year-over-year dollar
swing (current-quarter revenue minus an implied prior-year figure, back-solved
from the reported YoY growth rate) and labels it "Quarter driver" if it grew
or "Quarter drag" if it shrank. This is derived client-side purely from the
`revenue_usd_m`/`yoy_growth_pct` already in each highlight — it isn't a
company-disclosed decomposition, and it's only ever as good as whichever
products a company chose to call out in its own release. No extra curation
is needed to get this — it falls out automatically once `product_highlights`
has at least one entry with both fields populated.

## Limitations, honestly

Loss-of-exclusivity is genuinely hard to predict precisely: listed patents
can be delisted, invalidated, or settled around; 30-month stays and pediatric
extensions can push dates later; some listed patents don't actually block a
generic because of their use-code scope. This tracker surfaces the best
available public signal for *monitoring*, not a guarantee — always check the
"Sources" links in a drug's detail panel and, for anything decision-relevant,
the live FDA databases directly.

The Specialty Pipeline page is even more speculative by nature: every drug
on it is, by definition, not yet approved. Expected launch dates and peak
sales figures are estimates from analysts, companies, or press coverage --
not commitments. Phase 3 drugs fail regularly, timelines slip, and even a
positive trial readout is followed by a full FDA review that can still add
delays or rejections. Treat this page as a watchlist of what's coming, not
a forecast you can rely on for decisions.

The Earnings page covers 48 companies chosen to give broad coverage across
large, mid, and small market-cap tiers -- it is a curated cross-section of
the sector, not literally every publicly traded pharmaceutical company on
earth (there are hundreds of smaller and regional manufacturers not
included). Figures are a point-in-time research snapshot, not a live feed
-- companies report on different fiscal calendars, some report in non-USD
currencies (converted to USD at approximate spot rates, noted per figure),
and a couple of tracked companies were acquired mid-2026 and are shown with
their last public-company quarter rather than a current one (flagged via
each entry's `status` field). This page is for market monitoring, not
investment advice -- always check the "Sources" links for anything
decision-relevant.
